# Constitution

Non-negotiable principles for Math Game. Every spec, plan, task, and code review is checked against these. If a feature idea conflicts with a principle, the principle wins or the principle is amended here first.

## 1. No tests. No quizzes.
Nothing in the game is framed as an assessment. There are no placement tests, unit tests, or quizzes. Progress is tracked by playing games. The game always knows what the player can do because it watches them do it.

## 2. Fun first.
Every game must be fun on its own terms — something a player would choose to play even if it taught nothing. A worksheet with a skin is a failure. If a mechanic is only fun because of the stars attached to it, it is not fun.

## 3. Sophistication scales with the player.
A game about addition looks, sounds, and feels different from a game about limits. Art style, pacing, UI density, tone, music, and mechanical depth mature along with the skills. A 1st-grade world and a 12th-grade world should look like they belong to different games that share a universe.

## 4. Mastery, not completion.
Finishing a level proves nothing. Stars and progression reflect understanding that holds up over time, across representations, and without hints. Mastery can decay; the game revisits it.

## 5. Grades are worlds.
1st through 12th grade are twelve worlds. Each world contains skills that build on skills from earlier worlds. Within a world, skills form a graph, not a line.

## 6. Self-paced. Parent or teacher sets the starting world.
A parent or teacher chooses where the player begins. From there the player moves at their own pace in whatever direction the skill graph allows. The game never gates the player with an exam.

## 7. Common Core is the backbone, not the boundary.
The curriculum graph starts from the Common Core State Standards for Mathematics domains and progressions because they are a published, well-structured K–12 sequence. Skills, connections, and ideas outside Common Core are welcome when they make the game better or the math deeper.

## 8. Specs are the source of truth.
`specs/` drives the build. The curriculum is data, not prose, so levels and games are generated from it. Code that disagrees with a spec is a bug in one or the other, and the spec is fixed first.

## 9. The parent/teacher layer is a real feature.
Parents and teachers set the starting world, see progress, and attach real-world rewards to in-game milestones. This layer is PIN-gated and designed with the same care as the player experience.

## 10. Understanding over memorization.
Representations are mixed (symbolic, visual, verbal, physical). Strategy matters, not just answers. A skill is not mastered until it transfers to a representation the player did not drill.
